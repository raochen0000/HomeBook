## 2. 执行前准备

### 2.1 账号和数据

| 标识       | 准备要求                                                                          |
| ---------- | --------------------------------------------------------------------------------- |
| `O`        | 家庭 A 的户主，已绑定至少一种可恢复登录方式                                       |
| `M1`、`M2` | 家庭 A 的普通成员；用于记账人、成员筛选、转让及移除验证                           |
| `J`        | 单人家庭且无流水的用户，用于无损加入家庭                                          |
| `J-T`      | 单人家庭且有至少一笔流水的用户，用于验证加入前的删除警示                          |
| `F`        | 另一个多人家庭的普通成员，用于「自动退出后加入」验证                              |
| `O2`       | 另一个多人家庭的户主，用于验证户主不能直接加入                                    |
| `X`        | 不属于目标家庭的用户，用于 RLS/未授权验证                                         |
| 家庭 A     | 创建日期在当前月；至少有收入、普通支出、储蓄存入/取出、不同分类和不同记账人的数据 |

- 尽量使用一次性测试手机号/邮箱，并记录其家庭、邀请码和流水 ID，便于清理。
- 涉及删除家庭、退出家庭、账号注销的用例应使用专用账号；不要在生产真实家庭上执行。
- `INT`、`SEC` 用例必须连接目标 Supabase 环境；`DEV` 用例使用已安装的开发构建或候选发布构建，不能用 Expo Go 代替推送/相机/Apple 登录验证。
- 需要观察推送时，准备一台已授权通知的真机，以及一台用于触发家庭操作的第二设备。

### 2.2 统一检查点

除非用例另有说明，每次写操作都要同时确认：

1. 操作期间按钮防重复提交，成功后界面刷新且数据跨冷启动仍存在。
2. 失败时显示可理解的错误，输入/未提交数据不应无故丢失。
3. `X` 不能通过切换账户、重放旧链接或直接请求读取/修改不属于自己的家庭数据。
4. 中文和英文、浅色和深色模式下，长名称、长备注、动态字号不截断主操作。
