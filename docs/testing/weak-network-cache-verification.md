# 弱网与只读缓存验证

本清单用于验证已有账号重新打开 App 时的展示和刷新行为。账号切换、成员移除和记账写入只在测试账号与测试家庭中操作；不要为了验证修改正式账本。

## 准备

1. 安装包含本次原生依赖的新开发构建；模拟器构建步骤见项目 README。首次升级后的业务缓存需要在联网成功加载后才能生成。
2. 用测试账号联网打开首页、家庭页、报表，以及需要验证的记账、分类、预算和储蓄面板。等待加载完成，再等待数秒以便合并写入缓存。
3. 记录当前账期、筛选条件和页面展示；另外保留一个从未打开的账期或筛选条件，用于验证没有缓存的情况。

## 行为检查

1. 完全退出 App，断开设备网络后重新打开：已缓存的页面和记账分类应显示上次数据，并提示数据可能不是最新；未缓存的内容应显示「暂无可用数据，请联网加载」，不能显示为零或空账本。
2. 在断网状态填写记账表单并尝试保存：应提示网络异常、保留已输入内容，不应产生离线待提交记录。保存请求已发出后超时或网络中断时，需先联网检查账单再重试。
3. 恢复网络：过期的离线提示应消失；身份及家庭确认后，页面应后台更新。如果刷新再次失败，应显示可重试的错误提示。检查首页、报表及已打开的记账、预算、分类、家庭设置、储蓄和通知面板；通过测试家庭的另一设备产生的新数据应在刷新后出现，不应要求重新登录或手动清除缓存。
4. 在测试家庭中分别检查退出登录、切换账号、切换家庭和移除成员：不同账号或家庭的数据不能串用；断网期间可能暂时看到上次缓存，联网确认权限变化后应停止展示原家庭数据。
5. 模拟弱网和服务不可达：已有数据应保留，未加载的区域应提供失败或重试状态；检查首页、家庭页、报表、记账面板及相关 Sheet 的提示不遮挡主要操作。
6. 验证会话恢复：已有本机会话时冷启动不应闪现「请先登录」；认证暂时不可达时保留本机缓存；明确退出或确认会话失效后进入登录页。无本机身份且认证恢复失败时应提供重试，而不是断言用户已退出。
7. 断网时在报表切换已缓存与未缓存的周、年周期：已缓存周期可直接展示；目标周期或当前筛选所需数据没有缓存时，应立即提示「暂无可用数据，请联网加载」并保留当前报表，不等待超时。恢复联网后提示消失，周期可重新加载。

## 性能检查

- 在真机 Release 构建上，分别测量有缓存和无缓存的冷启动到首页可交互时间；使用相同设备、数据量和网络条件重复测量，并与 PRD 的冷启动目标比较。
- 使用接近真实规模的账本检查首页滚动、打开记账面板和报表切换；观察 JS 帧率、内存和启动期间磁盘读写，避免以开发模式或桌面脚本结果代替真机数据。
- 多次快速切换页面和筛选，检查请求数量与缓存写入是否合并；断网、重连及大数据量下确认无持续重试或明显卡顿。
- 检查记账保存耗时：分类、层级和隐藏状态会并行校验；弱网下应保持表单并在等待上限后给出相应提示。

自动化测试覆盖快照数量与体积限制、账号隔离、清理竞争，以及断网后恢复时的查询门控；它们不能替代上述真机交互和性能测量。
