# 一级、二级分类验收

## 数据库准备

使用独立测试项目和测试家庭；以下操作会修改目标项目的数据库结构。先备份并确认所选项目、环境和迁移状态，再在客户端使用新功能之前执行迁移。

1. 在 Supabase SQL Editor 中只读检查迁移记录和目标对象：

   ```sql
   select version, name
   from supabase_migrations.schema_migrations
   where version in ('20261101065802', '20261101120441')
   order by version;

   select
     to_regclass('public.family_category_layout') as category_layout,
     to_regprocedure('public.create_hierarchical_category(uuid,text,text,text,text,uuid,boolean)') as create_category,
     to_regprocedure('public.save_family_budget(uuid,text,bigint,boolean,jsonb)') as save_budget;
   ```

2. 确认目标项目已具备此前所有依赖迁移，包含 `20261101065802_recurring_daily_yearly_background.sql`。SQL Editor 手工执行的迁移不一定登记在迁移历史中；记录缺失或对象与记录不一致时，先核对实际结构，不要直接重复执行旧迁移。若新迁移的对象已经存在，也应先查明是否已经执行或部分执行。
3. 在同一个 SQL Editor 查询中，用 `begin;` 和 `commit;` 包住 [`20261101120441_hierarchical_categories.sql`](../../supabase/migrations/20261101120441_hierarchical_categories.sql) 的**全部内容**，确认无遗漏后一次运行。迁移涉及表、约束、RLS、触发器和报表及预算函数，执行时可能短暂锁表。出错时停止，先回滚并核对实际状态，不要直接重跑。
4. 成功后重复第 1 步的对象查询，确认三个对象均存在。SQL Editor 执行本身不保证更新 CLI 迁移历史；在后续使用 `supabase db push` 前，先核对并按团队既有流程协调迁移记录，避免重复执行。

家庭启用分类层级后，旧版客户端仍可记入原分类，但不能继续修改该家庭的预算；预算编辑需要使用更新后的客户端。

## iOS 模拟器验收

使用连接上述测试项目的模拟器，创建或使用专门的测试家庭。记账、分类调整、预算和定时规则操作会实际写入该项目。

- 新增分类时确认没有颜色选择器，输入名称后显示系统分配的颜色；保存后在记账、定时收支、列表和报表中核对颜色。编辑已有分类的名称或图标后确认原色不变，并分别检查浅色和深色模式。
- 在图标库中检查零食、烹饪、家电、充电、儿童用品等新增图标，选择并保存后在分类列表、记一笔和定时收支中确认显示；检查受支持的较低 iOS 版本。
- 新增和编辑分类时检查 14 个图标分组各显示两行、每行 6 个；编辑一个使用已从选择列表移除的图标的旧分类，确认不重新选图标直接保存时原图标仍保留。

- 在有旧流水和本月预算的单层分类下添加二级分类，并分别给一级、二级选择图标；旧流水应保留为「未细分」。
- 在「记一笔」确认只平铺二级分类，没有未归组分类或「交通未细分」等选项；不同一级下创建同名二级分类，点选时确认出现完整路径提示，再分别保存流水。
- 编辑原本记在一级的历史流水：不更改分类时应保留原分类；选择二级分类后应使用新分类。之前选中过的一级分类也不能在新流水中被默认选中。
- 在搜索结果和流水详情确认「一级 / 二级」路径；按一级名称搜索和在分类筛选中选择一级时，应覆盖其二级；单选二级应只匹配该分类。
- 在支出和收入报表确认一级金额、二级明细及旧流水汇总正确；进入下钻后成员和时间筛选仍生效。分类超过展示数量时，检查「其他」的多级下钻。
- 确认预算只能选一级或未归组单层支出分类，一级预算已用包含其二级与未细分流水；将有本月或未来预算的单层分类归组时应先要求调整预算。
- 检查普通成员与户主的预算权限，以及隐藏或停用一级前的二级、预算和定时规则影响提示；历史流水仍可查看，既有定时规则不会被自动修改。
- 检查切换家庭、重启应用后的上次分类选择，以及加载失败后的重试；留意长名称、动态字号和无障碍朗读。
