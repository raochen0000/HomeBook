# 家账多语言开发方案

> 状态：已拍板，作为实现对照。架构决策以 OpenSpec `app-i18n-en` 的 `design.md` 为准。  
> 范围：简体中文 + English。完成标准 = **P1 主路径双语**。  
> 拍板（2026-08-27）：① P1 才算支持英文；② 设备非中文默认 `en`；③ 系统分类显示翻译名；④ 法律英文直接进包；⑤ 系统推送本期按设备语言投递。

---

## 1. 目标

把「我的 → 语言」从 Toast 占位换成真正的中英切换，并覆盖：

- 登录、四 Tab、记一笔、流水、家庭、报表壳、设置 / 账号、帮助、关于
- 日期人性化标签、系统分类显示名、搜索双语命中
- 用户协议 / 隐私政策 / FAQ 英文正文（打进包）
- 系统推送标题 / 正文按设备 `locale` 投递

用户生成内容（备注、自定义分类、家庭名、昵称、目标名）保持原文。系统分类库内中文名与储蓄 RPC **不改**。

## 2. 非目标

- 繁体中文、「跟随系统」第三选项
- 语言偏好云端同步
- 改红收入 / 绿支出，改货币符号
- 短信 / 邮件模板双语、App Store 产品页
- 公开站点 `docs/public-site` 英文版
- 把预算预警 `payload.text` 改成结构化字段（英文推送该类用通用句）

## 3. 技术选型

| 层       | 选型                                              |
| -------- | ------------------------------------------------- |
| 设备语言 | `expo-localization`（SDK 56，`npx expo install`） |
| 文案     | `i18next` + `react-i18next`                       |
| 日期数字 | `Intl` + 当前语言；金额仍 `¥`                     |
| 偏好     | 本机 AsyncStorage，对齐深色模式                   |
| 推送语言 | `device_tokens.locale`（`zh` \| `en`）            |

`expo-localization` 的 config plugin 需要 **重新构建** Dev Client / TestFlight，OTA 带不走 InfoPlist。

```

  index.ts             统一 re-export
  instance.ts          i18n init、t()、setAppLocale（勿在此 import expo-localization）

  resources/en.ts
locales/
  zh-Hans.json         InfoPlist / 显示名

```

命名空间：`common` `tabs` `home` `record` `report` `family` `settings` `auth` `help` `legal` `notifications` `categories` `account` `search` `summary` `category` `budget` `savings` `feedback` `invite` `member`。

设置 UI 与令牌短码：`zh` / `en`。i18next 语言：`zh-Hans` / `en`。缺 key 回落 `zh-Hans`。

## 5. 语言解析

```
有存档 homebook.locale-preference.v1？
  是 → 用存档 zh | en
  否 → getLocales()[0].languageCode
         以 zh 开头 → zh
         其它       → en
```

切换：`i18n.changeLanguage` + Provider state。NativeTabs 里的 SwiftUI Host 不会改已挂着的原生文案，只重建 Tab 子树不够。切语言时给根 `Stack` 外包一层 `key={locale}`，拆掉整棵导航原生树再挂上；同时记下当前路由并 `replace` 回去，避免从「我的」掉回首页。默认不整包 reload。

系统权限弹窗跟随 iOS「设置 → 家账 → 语言」，不是 JS 开关。plugin 声明 `supportedLocales: zh-Hans, en`，`supportsRTL: false`。

## 6. 分类与搜索

中文存库名 → code（`food`、`salary`、`savingIn`…）→ `t('categories.<code>')`。`is_system === false` 原样显示。搜索对系统分类同时匹配存库名与显示名。

## 7. 推送

1. migration：`device_tokens.locale text not null default 'zh'`，check `zh|en`
2. `register_device_token` 增加 `p_locale`（带 default，旧客户端仍可用）
3. 客户端注册 / 切语言时上报当前短码
4. `push-fc` 按令牌 locale 选模板；非法值回落中文

App 内通知中心用客户端 `t()`，不依赖推送模板。

## 8. 部署顺序

先 DB（locale 列）→ 再 `push-fc` → 再带 i18n 的客户端。权限与桌面名必须新二进制。

## 9. 验证

- 中文设备首次启动为中文；非中文设备首次为英文
- 切 English 后 Tab / 首页 / 记一笔 / 设置 / 法律为英文，备注仍原文
- 系统分类显示 Dining 等；搜 Dining 与搜「餐饮」都能命中
- 切语言后已注册设备的令牌 locale 更新
- `pnpm test` 与 `tsc --noEmit`
